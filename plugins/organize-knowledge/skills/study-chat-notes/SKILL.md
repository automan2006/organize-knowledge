## 0.2.2 默认归档所有可视化卡片

正式整理必须执行 [可视化卡片默认双端归档](../notion-course-notes/references/visualization-cards.md)：除函数图表，还包括静态 HTML 对比卡、SVG/Canvas 图解和交互面板。默认保存可取得的 HTML、实际数据、CSS/JS 与原交互逻辑到 Notion 和 GitHub，关联到对应知识点；按资源包内容去重，缺源码不以截图冒充。遵守用户限定的目标，只升级插件不归档本聊天。卡片缺失不能因正文重复跳过。

## 0.2.1 每篇保存后登记主页链接

每篇 Notion 笔记保存并回读后，立即执行 [主页底部笔记链接](../notion-course-notes/references/homepage-note-links.md)：在所属课程、知识领域或书籍主页底部逐行添加该笔记的真实标题链接，包括日期目录下的专题直达链接；按页面 ID 去重，保留既有数据库与人工内容，不移动页面。回读确认后报告导航状态。完整重复仍跳过，不因升级批量补写历史导航；只保存 GitHub 时不写 Notion。


## 0.2.0 材料分类与精简边界

先执行 [图片、PDF 与三类资料规则](references/material-intake.md)；该规则优先于本文及旧引用中泛指“所有内容/所有科目全文保留、默认课程”的要求：课堂仅限本学期；课外知识另存知识；读书笔记按主题和书籍归类，读书聊天与书籍同目录，只有读书聊天允许精简。课堂、知识和原读书笔记继续完整保留。图片/PDF 逐页识别并保留原件，默认去重后同时保存 Notion 和 GitHub，重复不再写入。仅更新插件不创建学习档案。


# 整理聊天学习笔记

用中文处理当前这一条聊天。首次使用先核实使用者自己的 Notion 连接、归档位置与 GitHub 私有仓库配置。先读取 [任务选择与默认行为](references/task-selection.md)，确定本次目标与知识范围。**正常整理默认同时保存到 Notion 课程和已配置的 GitHub 私有仓库**：Notion 保留完整知识、可取得的图片及手机公式排版；GitHub 保存完整 Obsidian Markdown。普通学习问答、讨论插件、更新插件或只预览均不构成笔记归档指令。

用户已将 Notion + GitHub 设为正常整理的默认保存目标，调用本 Skill 即执行，无须反复确认；原有聊天中可复制的 Obsidian Markdown 也照常交付。**只有用户明确限制目标、交付或范围时才改为选择性执行**；“只存 Notion”“不要上传 GitHub”等排除对应任务，“只整理螺栓连接”等仅限定内容、仍保存两处。用户给出其他明确输出要求时遵从。

**所有科目统一执行 [完整学习档案标准](references/complete-learning-archive.md)**：完整知识讲解、原始提问与原回答全文、连续追问、每一步推导/计算及其原因、对应位置的图片/交互图、易错点、知识联系和复习自测都要保留。Notion 使用课程 → 真实学习日期总目录 → 详细专题；Obsidian 使用学习记录与概念网络。不能用几条公式或重点摘要代替完整学习过程，也不将引用的科目和日期当成本次要创建的记录。

1. 阅读 [完整学习档案标准](references/complete-learning-archive.md)、[知识提取规则](references/extraction.md) 与 [重复检查](references/deduplication.md)，逐条盘点可读原文中的知识、问答链、例题和媒体；未限定范围时覆盖当前聊天的全部学习内容。建立来源 → 日期/专题 → 各已选目标落点的覆盖清单；仅摘要或旧消息不可读时列出缺口，不编造原问答。Notion、GitHub 分别读取旧内容，完整重复的目标直接跳过，不能在一边重复就略过另一边；缺原问答或解释的摘要笔记不算完整覆盖。用户图片与助手示意图分别列清单，归档图片时主动取得真实文件，不能只登记文件名。

   可交互函数/图表单独建清单并执行 [交互图表流程](../notion-course-notes/references/interactive-charts.md)，保留真实源代码、数据、控件与参数；截图不当作交互原件。Notion 使用原生 HTML embed，GitHub 备份源文件及 Markdown 引用；源码缺失或未实测交互时如实报告。
2. **Notion 被选中时（默认）**：按 [Notion 课程笔记 Skill](../notion-course-notes/SKILL.md) 归类，在已确认课程内按真实学习日期分别组织目录和详细专题，并保留对应原始问答；日期未知时标待核实。先去重再写入与上传图片，重复且完整时返回原页、不刷新或重写。新增内容保存后回读逐项验证，保留完整解释、公式、例题及图片流程；跨日期建立真实专题链接，记录真实课程依据，无匹配与查询失败分开说明，不擅建课程。
3. **GitHub 被选中时（默认）**：按 [Obsidian 概念笔记 Skill](../obsidian-concept-notes/SKILL.md) 生成完整 Markdown，保留 YAML、公式和 `related_candidates`，读取 [归档配置](../obsidian-concept-notes/references/github-config.md) 与 [课程/领域分类](../obsidian-concept-notes/references/classification.md)。同课程复用目录、新方面新建领域；同名或改名但内容重复均跳过，确有新增才逐篇创建并验证真实提交，仍不覆盖旧文件。未限定时检查全部本次笔记，限定时只处理对应范围。
4. **Obsidian 聊天导出被选中时（正常完整流程保留）**：提供可复制 Markdown 正文。用户说只保存、不贴正文或只执行某个保存目标时可跳过；只要求导出且排除了保存目标时，仅执行导出。GitHub 文件生成与聊天全文交付分别遵守最终选择，不互相冒充完成。
5. 仅报告已选择任务的结果，分别统计新增/更新、重复跳过、待核实/失败。Notion 返回课程、日期目录/专题的真实链接、来源可读范围，以及原问题、原回答、追问链、例题和媒体的覆盖数/应覆盖数；GitHub 返回每篇分类、已有或新建路径、真实提交或“重复跳过、无新提交”。全部重复时明确本次没有新增写入，不把跳过称为新建成功。原文缺失、所选任务有缺图、失败、未核实或尚未交付批次时标“部分完成”，不把未选择的任务列成失败。只有完整原文已读且逐项核对无缺口，才称“全文完整归档”。

默认分别验证 Notion 与 GitHub，一项失败继续完成另一项，准确报告部分完成；Notion 失败保留其草稿，GitHub 失败明确“尚未保存到 GitHub”并保留待上传文件。用户明确只选一处时不访问另一处，也不把失败内容改投被排除的目标。导出过长时分批标号，不静默截断或宣称未完成部分已经交付。

本插件使用所选目标的账号连接，无须本地 Obsidian 库或 Obsidian API。Web、Windows 和 iPhone 按实际安装、连接及文件能力执行，不能将包保存成功说成三端实测成功。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](references/history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。

## 相同内容只保存一次

完整保留原文与去重同时执行：已在目标中完整保存的相同问答、解释、图片和交互源不再重复上传，补传历史和同批次重复也一样。全部重复时不新建页面/文件、不刷新日期、不生成补充报告或提交，直接返回已有链接并报告“重复跳过”。部分重复时只补新增或缺失部分，重复原文引用已验证完整位置；不能改标题或加后缀重存整篇旧内容。不同追问、不同答案、缺失全文/步骤/媒体仍须补齐。Notion 与 GitHub 分别核对，只补缺失目标；不自动清理历史重复笔记。
