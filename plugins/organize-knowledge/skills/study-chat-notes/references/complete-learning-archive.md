# 所有科目统一使用的完整学习档案标准

本标准适用于所有课程与知识领域，也是三个 Skills 的默认内容标准。一次调用的目标和范围仍由 [任务选择](task-selection.md) 决定；范围变小不降低该范围内的完整度。不能把一次学习过程压缩成几条公式、重点摘要或概念名。用户仅更新插件时，不执行学习笔记归档。

## 先核实可访问的原文

只整理实际可读的聊天、附件、产物、用户提供的导出文件及已连接工具真实读取的笔记。不承诺自动读取账号全部历史聊天。聊天摘要只能作为查找线索，不能还原缺失的原始提问和答案。不能凭记忆、截图片段或课程常识编造原话、日期和解释。

开始时记录来源范围：完整原文已读、只读到部分、仅有摘要、附件缺失。早期消息被压缩或旧聊天不可访问时，标为“基于当前可访问内容，非全文完整归档”，列出具体缺口；先保存可核实部分，需补齐时说明可提供聊天导出或在原聊天调用。不要因新标准自动声称旧笔记已经完整，也不在没有要求时批量改动历史笔记。

## 逐条建立学习过程清单

按原消息顺序盘点学习内容，不能只按主题选取看起来重要的片段。每条使用真实消息定位；若平台没有消息 ID，可使用本次读取中的顺序号并注明它不是平台 ID。

- **知识项**：定义、原理、公式、符号和单位、完整推导、假设、适用条件、边界、分类比较和应用。非数学课程保留论证、材料、步骤、反例和概念区别，不强行制造公式。
- **问答项**：每个实际学习提问的原文及其对应的可见原回答；连续追问按父问题串联，尤其是“为什么”“怎么来的”“有什么区别”“为什么不能这样做”。同一概念多次追问不能只留最后结论。
- **例题项**：完整题目、已知与所求、假设、解题理由、逐步代入/运算/单位换算、每步依据、结果、判断和自检。不能把多步计算合并为只有起式和答案的一行。
- **媒体项**：用户图片、助手配图、交互图表分别登记，并绑定到具体知识项/问答项；保留题图、图注、公式、参数和来源。图片和交互原件继续使用既有上传与验证流程。
- **纠错与关系项**：原误区、改正原因、正确结论、仍有冲突的地方，以及概念之间的前置、对比、推导和应用关系。
- **复习项**：将真实疑问转换成自测题，给出对应答案/解析的位置；与尚未解决的问题分开。新增自测或补充说明标明是本次生成，不冒充用户原问题。

每项至少记录来源、所属科目/专题、可核实的学习日期（可为空）、完整内容或原文可用状态、关联问答链、所选目标中的落点/已有覆盖证据与缺口。日期未知时，归档日期和学习日期分开，不能把当前日期倒填为旧消息的发生日期。

## 专题讲解和原始问答都保留

专题正文可以重新编排，必须保留概念解释、每一步推导、物理或直观说明、条件差异、比较、反例、用户误解和纠正过程。旁注或重点卡片只作导航，不能替代完整正文。

每个专题保留对应的**原始问答链**：用户原问题逐条原文引用，助手可见教学回答保留全文，按原顺序标明首问、追问和后续纠错。原文层保留所选范围内的寒暄，内部工具日志不属于可见对话；讲解中的铺垫、举例、提问和重述不能仅因篇幅长而删掉。专题与原问答可共用同一段原解释，避免机械复制；不能用一句“已解释”或只给聊天链接代替回答内容。所选范围内默认逐条全文保存，不需要用户另外要求逐字保留。

原答案有错误时：专题正文用经过核实的正确结论；原始问答里的旧答案明确标为“后续已纠正”，附真实纠错位置，不能将错误悄悄抹去或继续当正确知识。没有原文的部分只写已核实的整理内容并标原问答缺失，不能加引号冒充原话。

同一原问答涉及多个概念时，指定一个完整存放位置，其他专题指向实际已保存页面/文件及该问答的位置。每篇专题都能定位与自己有关的原问答及完整回答；链接仅用于本次归档内的可核实去重，不能以指向不可访问旧聊天的链接代替原文。Obsidian 不预写概念双向链接，使用实际文件的相对链接或候选关系。

## Notion：课程 → 日期学习总目录 → 详细专题

复用已确认的课程主页，不新建或移动课程。按**真实学习日期**分别建立/复用当天的学习总目录，其下按知识点放详细专题，专题包含完整讲解、例题、对应原问答、媒体、易错点、知识联系与复习自测。短内容可放在当天页的完整专题区，长内容拆为专题子页。跨科目先分课程；跨日期先分日期。这里的结构适用于所有科目，示例科目和示例日期不是要自动创建的固定数据。

日期缺失的内容放“学习日期待核实”区，保留归档日期并注明差异；不为示例日期造记录。混有多个日期且部分未知时，已知日期分别归档，未知部分保留来源与待核实状态。当天总目录包括主题、对应专题、原问答覆盖和未解决问题；同一课程跨天的知识联系使用实际页面链接，避免仅按日期将知识隔断。

沿用 [长文字学术模板](../../notion-course-notes/references/academic-template.md) 的原生颜色、导航及模块。图片/HTML embed 紧跟它解释的知识点或例题，复杂图放该专题全宽区，不集中堆到文末。长公式按手机宽度拆行/缩放，计算结果之后的判断另起块。长推导和原始问答用全宽正文或有明确名称的折叠区，不为适应侧栏删字。

## Obsidian：日期线索和概念网络同时保存

保持与 Notion 等量的知识、问答、例题和媒体覆盖，但重新组织为课程目录、按真实日期命名的学习记录，以及稳定命名的概念/方法/例题笔记。学习记录保留按序的原始问答链和当天学习路径；概念笔记完整讲解，并定位相应学习记录中的原问答。也可将问答全文保留在概念笔记，学习记录提供真实定位；不能两处都只留摘要。

所有 Markdown 保留现有 YAML、LaTeX 和 `related_candidates`；日期记录、概念关系都给出关联原因。只写可核实的来源和学习日期，不用归档时间冒充学习时间。保持用户选择的后续插件生成双向链接方式；本流程不擅自预写 `[[概念]]`，不操作本地库。GitHub 仍复用同课程分类，Markdown 原字节归档、同名不覆盖；新日期不意味着新课程或新领域。

## 完整度优先的去重与交付

执行 [逐目标重复检查](deduplication.md)。重复判定不仅比较概念和公式，还包括原始问题、追问链、完整回答、推导中间步骤、例题依据、纠错和媒体。旧页仅有摘要/最终公式，缺本次可取得的完整解释或原问答，属于待补；新的问题或解释即使围绕旧概念，也不能因“主题相同”被跳过。日期或来源定位单独变化、没有新增学习内容时仍跳过，不为每日目录反复写入同一档案；旧笔记已经完整存放同一问答链时复用其真实位置。

保存前将每一条学习项、每个原问题和回答、每道例题及每个媒体映射到各已选目标；保存后读取实际正文，逐条核对，不只检查标题或提交成功。长文分批写入/交付时建立分片清单，回读末尾及连续性，不能因工具限制静默截断。检查一个知识点的公式完整，不等于其问答和解释也完整。

交付报告说明实际来源范围，分别统计原始问题、对应回答、追问链、专题、例题、用户图片、助手图及交互图表的覆盖数/应覆盖数，列明缺失原文和仍待解决的问题。可使用“当前可访问范围已核对完成”，只有完整原文确实已读且每项均有可验证落点时才称“全文完整归档”。源记录缺失、某目标未保存/未核实、附件缺失或批次未交付时都标“部分完成”，不能仅有几条主要知识点就声称全部完成。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。
