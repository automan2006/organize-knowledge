# 写入前分别检查 Notion 与 GitHub 重复

正常流程仍保存 Notion + GitHub，用户明确限定时按其范围执行。在每个已选目标写入前比较其已有内容；**完全重复且已完整保存的知识不再次创建、更新或上传**。只修改插件不触发本次聊天归档。

“完整”按 [所有科目完整学习档案标准](complete-learning-archive.md) 判断：知识和学习过程都必须覆盖。不能仅因旧页有同一公式、概念摘要或最终答案，跳过本次可读的原始问答、追问、解释或中间步骤。

## 判断知识是否重复

1. 按已确认课程/领域和具体知识点检索已有笔记，读取候选全文及图片归档状态。先用标题、别名、分类、来源及指纹缩小候选，但不能仅凭标题或“以前整理过”就跳过。跨聊天也要识别同一课程中已讲过的知识。
2. 比较实际定义、条件、公式、符号/单位、完整推导、例题的每一步及原因、操作/代码、纠错、原始问题与回答全文、连续追问、独特图片和交互源。新的实际提问、为什么/怎么来/区别的解释、未存的问答链及缺少的计算步骤都是新增学习内容，即使公式和主题相同也不能忽略。只改变标题、日期、来源定位、排版或用词，而没有新增知识或学习过程时，视为重复；不同课程语境也不盲目合并。
3. 候选完整覆盖本次所选知识、对应原始问答和追问链，且相应媒体已验证保存时，记录“内容重复，已跳过”及原笔记链接/路径，不写入该目标。来源、日期或统计数字单独变化不成为更新旧笔记的理由，不为日期目录重存相同问答，也不为了记录一次跳过而提交回执文件。
4. 部分重复时保留新知识、原始问答/追问、缺失解释/步骤、纠错或新增媒体：Notion 在已可靠识别的插件笔记中只追加/修正对应部分，不重贴旧段落；不能可靠定位时以增补笔记保存新增内容及必要上下文，不改人工内容。GitHub 未变化的笔记跳过，确有新增的学习记录或概念笔记保存为新文件/新版本，保留独立理解所需上下文，仍不覆盖旧文件。不能因为含有重复段落而丢弃新增学习过程；已经完整保存的同一问答可复用真实落点。
5. 文本重复但原页尚缺图、图片未插入或回读不完整时，不标完整重复；只补缺失部分，复用已确认可用的图片块/附件，避免同一张图反复上传。

   交互图表按实际源码、数据、控件/参数配置与验证状态一起比较。旧页只有截图或缺少原生 HTML embed、GitHub 尚无源文件时属于待补，不能被相同正文或同一张预览图去重掉；相同源码和交互已完整归档时才跳过对应目标。
6. 候选无法读取、检索截断、权限/连接失败时，标“去重待核实”，停止该目标受影响笔记的写入，继续其他已明确目标和笔记；不能把查询失败当成“没有重复”或“确认重复”。

Notion 与 GitHub **独立检查**。Notion 已有、GitHub 缺失时只补 GitHub；GitHub 已有、Notion 缺失时只补 Notion。不能在一边发现重复就跳过另一边的检查。模型整理出的语义等价需以实际读到的旧内容为依据，不能凭空声称已比较。

## Notion 执行位置

在创建页面、修改段落及上传图片**之前**执行检查。内容已经完整存在时返回原页，`本次新增/更新=0`；不刷新日期、不重写“归档信息”、不为一次重复调用新建同主题页。已有内容指纹只作候选证据，旧页是否新增人工内容、缺图或被修改仍需回读确认。

跳过是成功处理的一种结果，报告“已存在，跳过”，不把旧页称为本次新建，也不要求用户重复确认才能跳过。

## GitHub 连接器与辅助程序

连接器先读取对应分类的候选 Markdown；同名或不同文件名但知识等价时，都可确认跳过。只有**内容有新增**的同名笔记才另取后缀创建，禁止通过加日期/后缀绕过去重。跳过项返回已有路径与链接、本次无新提交；不要伪造新 SHA。

[archive_github_notes.py](../../obsidian-concept-notes/scripts/archive_github_notes.py) 增加一层保守的自动校验：在目标分类目录及其子目录读取已有 `.md`，比较内容指纹；本批次相同内容也只保存一次。目录读取失败或达到 Contents API 列表上限时停止受影响项，要求完整树/候选检查后再继续，不能默默漏查。

程序指纹仅统一换行，并忽略明确的导出/来源字段：`created`、`updated`、`created_at`、`updated_at`、`exported_at`、`archived_at`、`archive_date`、`generated_at`、`source`、`source_chat`、`source_chat_url`、`source_message_id`、`source_locator`、`plugin_version`、`content_fingerprint`。保留其余 YAML、公式、数字、代码、正文与 `related_candidates`，不使用会误删知识的模糊阈值。更换标题或改写正文的语义等价由模型在调用程序前比较，程序本身不保证识别所有语义重复。

实际上传时仍使用未经改写的原始字节。重复项状态为 `skipped_duplicate`，含真实已有路径、blob SHA 和指纹，`new_commit=false`，不含伪造的本次提交 SHA；`created_count` 与 `skipped_duplicate_count` 分开统计。`all_verified=true` 可表示所有项目均已验证新建或确认重复，并不等于每篇都创建了提交。

## 最终报告

对每个已选目标分别给出：新增/更新数量、重复跳过数量、待核实/失败数量；跳过项给已有链接或文件路径。全部重复时直接说明“本次没有新增写入”，仍可按用户选择在聊天中交付 Markdown。已存在数据不删除、不合并、不搬移。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。

## 重复内容不再保存（适用于全文与补传）

全文保留表示每份独特原文都完整可读，不表示重复上传同一份内容。按各目标实际已保存内容检查：跨调用、跨聊天、补传文件重叠和同批次中的完全相同段落/问答/图片/交互源，只保留一份已验证原件。不得通过改标题、换日期、加后缀、另建“全文版/补充版”绕过重复检查。

- 全部内容已完整存在：不新建页面、目录、附件、Markdown、补充报告或提交；不刷新旧页日期、统计和缺口状态。聊天中返回真实已有链接/路径，说明“重复跳过，本次新增 0”。
- 部分重复：只保存新增原文、不同追问、未保存解释/计算步骤、纠错或缺失媒体。重复正文引用已验证存放位置；引用须能定位完整原文，不能用不可访问的聊天链接代替。为新内容保留必要上下文，不把整篇旧笔记重存一遍。
- 同批次重复：先建立已处理项清单再上传，同一内容只写入一次。来源顺序确有新增且用户需要学习记录时，可在有实质新增的学习记录中用定位引用表达，不为重复调用单独写一次出现记录。
- 文本比较保留公式、数字、条件、单位、代码与回答差异；仅忽略无意义的换行格式差异。语义相近但原话不同不能直接当作原文重复；相同问题后有不同答案或新追问，保留新部分。旧摘要缺全文仍应补齐。
- 媒体按真实内容/源文件核对，临时下载地址变化不代表新图片。目标中已有可用媒体则复用；未保存成功、已不可访问或缺交互源时仍应补齐。
- Notion 和 GitHub 独立判断：只补缺少的一边。读取失败或无法确认完整覆盖时报告“去重待核实”，不盲目创建重复副本，也不谎称重复。
- 本规则只阻止后续重复保存，不自动删除、合并或搬移已有重复笔记。
