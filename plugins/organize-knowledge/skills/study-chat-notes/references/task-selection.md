# 只执行本次选中的任务

## 默认与目标选择

- 普通学习问答继续正常回答；只有实际提出整理/保存要求时才开始归档。只修改插件、讨论功能或预览不写入外部应用。
- “调用 Organize knowledge 整理当前学习聊天”“整理笔记”等正常请求，**默认同时整理并上传到原有 Notion 课程，以及保存完整 Markdown 到已配置的 GitHub 私有仓库**。用户已经明确设定这个长期默认，无须每次再询问是否上传 GitHub。
- Notion 保存、GitHub 保存、聊天中 Obsidian 正文导出是可分别控制的任务。正常完整流程保存前两处，并保留原有可复制 Markdown 交付；只有用户限定目标或说不贴全文时才相应跳过。GitHub 保存始终需要完整 Markdown 文件，不能因关闭聊天全文而省略文件。
- 只有用户提出明确限制时选择性执行：“只/仅/不要/不用”限制目标或内容；用户完整列出排他任务范围时按该范围执行。仅提到 Notion 或 GitHub 不自动取消另一默认目标。“也/再/同时”追加任务，明确指令无需重复确认。
- 单独点名 `$notion-course-notes` 或 `$obsidian-concept-notes` 是调用独立单项功能，执行所点名的 Skill；用户说明还要其他目标则由主流程调度。泛称 Organize knowledge 或 `$study-chat-notes` 的正常整理使用 Notion + GitHub 默认。
- 在同一项尚未完成的工作中，“继续”保留已确定目标；新的正常整理任务也使用 Notion + GitHub，除非用户明确限制或改变长期默认。
- “完整整理/全部知识”指所选内容覆盖完整；正常流程仍保存两处并交付可复制 Markdown。“Notion、Obsidian、GitHub 都要”也按完整流程执行。引用或举例中的动作不当成当前执行指令。

## 选择部分内容

所有科目都默认执行 [完整学习档案标准](complete-learning-archive.md)，不需要用户再强调“详细”才保留原始问答、连续追问、推导和逐步计算。用户明确要求简短预览时按预览交付；这不改变后续正常归档的完整标准。举例中的课程、旧日期与问答不构成实际回填历史笔记的指令。

用户指定只处理某门课、某些概念或某几篇笔记时，只处理该范围，**保存位置仍默认两处**；只有明确限制保存位置时才排除相应目标。单项图片补传等具体维护操作按指定动作执行，不无端生成新笔记。未限定内容时覆盖当前可读聊天的全部学习知识。同一请求可分别限定不同目标，例如“全部保存 Notion，只把公式笔记上传 GitHub”。执行前形成内部目标/范围清单，不需要为明确指令额外询问。

所选知识点的完整解释、条件、公式、例题和相关图片仍需保留；“选择性执行”不等于擅自缩短知识点。上传 GitHub 所必需的内部 Markdown 生成不等于用户要求在聊天中导出 Obsidian 全文。

## 指令示例

- “整理当前聊天。” → Notion + GitHub，并照常交付可复制 Markdown。
- “完整整理当前聊天。” → 同上，覆盖全部可读学习知识。
- “只整理螺栓连接。” → 仅这部分内容，仍保存两处并交付对应 Markdown。
- “整理到 Notion。” → 按正常默认仍保存 Notion + GitHub；“只整理到 Notion”才关闭 GitHub。
- “这次只上传 Notion，不要 GitHub。” → 仅 Notion。
- “只给我 Obsidian Markdown。” → 仅在聊天中导出，不写 Notion 或 GitHub。
- “只上传螺栓连接这篇到 GitHub。” → 只保存选中的一篇，执行课程/领域分类、同名保护和提交验证。
- “正常整理，也给我 Obsidian 全文。” → Notion + GitHub + 聊天中的 Obsidian 正文。
- “整理到 Notion，同时把公式笔记上传 GitHub。” → 完整 Notion + 仅公式笔记的 GitHub 保存。
- “三个目标都做，但不要上传 GitHub。” → Notion + Obsidian。
- “先预览，不上传。” → 仅预览，无外部写入。
- “更新这个插件。” → 只更新插件，不归档当前聊天。

## 输出与失败

默认目标不变，但每个目标必须先执行 [重复检查](deduplication.md)：完整重复时不写入该目标，返回原链接；新增内容才保存。重复跳过不算失败，也不代表另一个目标一定已经保存。

只报告选中任务的实际结果及必要限制。未要求的导出/上传不标“待完成”或失败，也不强行补做。已选择任务之间独立核实：失败不改投未选择的目标，不伪造页面、文件路径、提交或同步成功。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。
