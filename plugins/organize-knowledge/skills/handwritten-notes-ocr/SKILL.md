# 手写笔记识别与校对

在学习图片、拍照笔记、扫描 PDF 或印刷/手写混排材料中发现手写内容时使用。使用宿主当前可用的图像读取、视觉或 OCR 能力；本 Skill 定义识别和校对流程，不自带 OCR 引擎，也不保证所有字迹可辨。只要求识别/校对时交付结果，不自动写 Notion/GitHub；在 Organize knowledge 归档流程中按主流程已选目标保存。

## 读取与定位

1. 先取得并查看真实原图，PDF 按页查看实际页面。登记原文件名、图片编号或 PDF 页码及已读范围；可计算时保存原件 SHA-256。文字提取为空不代表没有手写内容；没有原件访问或图像能力时指出具体缺失文件/页段，不从文件名或聊天摘要补造原文。
2. 按标题、段落、公式、表格和图示划分区域，建立稳定编号，如“图1-R01／左上定义”“PDF第3页-R02／右下受力图”。原图始终保留；必要时另做旋转、放大、裁剪用于辨读，标为处理副本并说明其在原图的位置，不能替换原件。透页、模糊、遮挡和截断逐项登记。
3. 逐区域识别手写中文、英文、数字、工程符号及图中标注。保留原文顺序、层级、表格关系、箭头指向和图例对应；混排材料区分手写补注与印刷内容。不能仅转写正文而遗漏图上的字母、尺寸、公差、坐标轴、单位、箭头标签或公式旁条件。

## 公式与校对

- 核对公式结构、上下标、分数、括号、根号、积分/微分、向量、希腊字母、正负号、小数点、指数、单位及大小写。易混的 0/O、1/l/I、v/ν、p/ρ、u/μ、x/×、减号/连字符必须回看原图；上下文可提示候选，不能代替字迹证据。
- 明确可辨的公式转为 LaTeX，保留符号原貌与单位；语义解释另列，不能将猜测填入转写结果。不确定字符用“〔待确认 H01〕”，无法确定结构则将整式或局部区域标待确认；不要输出看似完整、实际猜出的公式。
- 所有区域完成后对照原图复核一遍，重点检查数字、符号和量纲。数学验算和知识判断只用于指出可能问题，不得为了使公式成立而悄悄更改原笔记。可辨但疑似写错的原文照录，在“校对建议”中另列建议及依据；原文转写、用户确认、推断建议分别标明。
- 无法辨读处明确写“待确认”，可列有字迹依据的少量候选，并提供区域编号、前后文及影响。不要编造概率或声称已经人工确认；同一疑点用同一编号关联公式和待确认列表。

## 输出与原图对应

按文件/页码 → 区域组织，每一区域包含：

- 来源定位：原图/页码、区域编号及位置说明；只有实际测量过才写坐标。
- 原图：可访问原件或已保存的真实链接，方便直接复核；长页可附局部副本但仍保留整页。
- 识别结果：可辨原文、LaTeX 公式、图中标注及其对应关系。不把整理摘要冒充逐字识别结果。
- 校对状态：已对照原图复核／待确认，并列疑点编号。视觉自查不等于用户确认或外部 OCR 实测。

最后给出已读页/区域范围、仍缺区域与待确认清单。来源完整、图像清晰也不等于识别必然准确，不声称百分之百正确。材料过长时分批编号并维护覆盖清单，不能只读前几页便称全部识别。

## 接入归档与后续确认

归档时再按 [材料分类](../study-chat-notes/references/material-intake.md) 判断本学期课堂、知识或读书笔记；“手写”只是来源形式，不另建与学科脱节的顶层类别。识别原文层保持完整，原件保存执行已有 [图片流程](../notion-course-notes/references/images.md) 和材料原件规则，Notion/GitHub 两端分别验证。原图就近对应转写区域，Markdown 只引用真实交付文件，保留既有 YAML、公式及 related_candidates。

可附 `source_format: handwritten`、真实来源定位及待确认项，但没有原件哈希时标未知，不编造。未解决字符在两端均保留“待确认”；原件保存失败时识别结果可继续交付，整体归档标部分完成。保留已有主页链接和可视化卡片归档流程。

用户补充清晰原图或确认字迹后，按区域和疑点编号补齐，记录“用户确认”或“新图辨认”依据；与既有结果逐项比较，只补新增/修正，不重复上传原图、不覆盖 GitHub 同名旧笔记。待确认列表已保存且完整相同则跳过；确认消除了不确定性属于实质更新，不能被正文近似去重忽略。无外部保存指令时，只在聊天中更新识别结果。
