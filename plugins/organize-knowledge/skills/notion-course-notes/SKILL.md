## 0.2.4 课堂检测与错题归档

课堂正式整理完成后由主流程调用 [classroom-knowledge-check](../classroom-knowledge-check/SKILL.md)，默认出五题十分钟试卷，先不给答案；交卷后统一批改，按80分与两道核心题80%门槛判断本次达标，完整测试和薄弱点默认按本轮所选目标自动保存。非课堂、独立 OCR、预览、插件更新不自动出题，用户明确不测试则跳过。单独保存 Skill 不重复启动考试；涉及检测记录时执行新 Skill 的来源定位、轮次、去重和课堂检测子目录规则。


## 0.2.3 手写笔记识别与校对

发现图片或扫描 PDF 中的手写内容时，先调用 [handwritten-notes-ocr](../handwritten-notes-ocr/SKILL.md)：逐页/区域识别中英文、数字、工程符号、公式和图中标注；保留原图并建立转写对应，无法辨认处标“待确认”，不猜测。再按既有课堂/知识/书籍分类、去重及所选目标归档。只要求识别时不自动外部保存，用户确认后的新增校对属于实质补充。


## 0.2.2 默认归档所有可视化卡片

正式整理必须执行 [可视化卡片默认双端归档](references/visualization-cards.md)：除函数图表，还包括静态 HTML 对比卡、SVG/Canvas 图解和交互面板。默认保存可取得的 HTML、实际数据、CSS/JS 与原交互逻辑到 Notion 和 GitHub，关联到对应知识点；按资源包内容去重，缺源码不以截图冒充。遵守用户限定的目标，只升级插件不归档本聊天。卡片缺失不能因正文重复跳过。

## 0.2.1 每篇保存后登记主页链接

每篇 Notion 笔记保存并回读后，立即执行 [主页底部笔记链接](references/homepage-note-links.md)：在所属课程、知识领域或书籍主页底部逐行添加该笔记的真实标题链接，包括日期目录下的专题直达链接；按页面 ID 去重，保留既有数据库与人工内容，不移动页面。回读确认后报告导航状态。完整重复仍跳过，不因升级批量补写历史导航；只保存 GitHub 时不写 Notion。


## 0.2.0 材料分类与精简边界

先执行 [图片、PDF 与三类资料规则](../study-chat-notes/references/material-intake.md)；该规则优先于本文及旧引用中泛指“所有内容/所有科目全文保留、默认课程”的要求：课堂仅限本学期；课外知识另存知识；读书笔记按主题和书籍归类，读书聊天与书籍同目录，只有读书聊天允许精简。课堂、知识和原读书笔记继续完整保留。图片/PDF 逐页识别并保留原件，默认去重后同时保存 Notion 和 GitHub，重复不再写入。仅更新插件不创建学习档案。


# Notion 课程学术笔记

首次使用先核实自己的 Notion 连接及使用者指定的课程位置，不自行挑选课程库。明确调用并要求保存即授权在已配置位置创建本次笔记与图片；只预览时不写入。按 [任务选择规则](../study-chat-notes/references/task-selection.md) 执行：Organize knowledge 的正常主流程默认同时保存 Notion + GitHub，由主流程分别调度；单独调用本 Skill 执行 Notion 这一项。用户明确限定时只执行所选目标与内容范围，并建立对应的 [知识清单](../study-chat-notes/references/extraction.md)。

## 课程与归档

先读 [所有科目完整学习档案标准](../study-chat-notes/references/complete-learning-archive.md)，再读 [课程位置配置](references/course-config.md) 和 [长文字模板](references/academic-template.md)。必须完整保留可访问的原始问题、原回答和连续追问，推导、比较、每步计算及原因不能缩成课堂摘要。有题目、计算或推导时必须读取 [手机公式与分步计算](references/formula-presentation.md)，根据公式宽度选择字号，长式缩小、必要时拆行；计算结果之后的判断与最终取值另起块。用原生数学块和彩色框突出重点，不能一律放大，也不能把全部计算挤成普通正文。本插件依赖现有 Notion 连接，不自建持有 Notion 凭据的服务。

1. 先检查 Notion 工具权限；根据当前 access map 使用可用搜索工具。AI search 不可用时用普通 search，避免使用套餐限制字段。读取 `notion://docs/enhanced-markdown-spec`（通过 Notion fetch 或其资源接口），遵守当前工具 schema，不假设参数。
2. Fetch 配置的课程库/数据源，按真实 schema 查询课程并核实目标页面。多候选或找不到匹配时仅询问课程归属；不擅自建立课程或改数据库 schema。记录确认的课程名称、课程页面 ID 和链接；未找到匹配与连接失败/查询不完整分别报告。主流程启用 GitHub 保存时（正常默认）将课程依据传给其分类步骤，并可继续其已确认的新领域归档；Notion 无归属的部分标待指定位置，不伪造课程。用户明确排除 GitHub 时不以其作为替代保存位置。
3. 默认采用“已确认课程主页 → 真实学习日期总目录 → 详细知识专题”。同课程同日目录先查找并复用，长专题建立子页，短专题可保留在当天页的完整分区；每个专题包含完整讲解、对应原始问答链、例题、媒体、易错点和自测。跨课程分别归档，跨日期分开组织并建立真实知识链接。学习日期未知时标“学习日期待核实”，另记归档日期，不从当前日期、示例日期或科目名推断历史。没有新增学习内容时不为了目录再写一次；不自动重排旧归档或移动人工页面。复用课程体系，不将聊天整理冒充实际“上课记录”。
4. 在创建/修改页面与上传附件前执行 [逐目标重复检查](../study-chat-notes/references/deduplication.md)：检索同课程、同知识点的旧笔记并读取实际内容，不限于同一聊天。完整覆盖包括原问题、原回答、连续追问、推导中间步骤、例题依据、图片及应有的交互图表；旧笔记只有摘要或最终公式不能判完整重复。已经完整覆盖时返回原页并标“重复跳过”，不更新正文、日期、目录、归档信息或重复上传。只有新增学习内容、纠错或缺失项补齐才在已识别的插件笔记中定点追加/修订，保留人工段落；无法可靠定位时保存增补笔记及必要上下文，不覆盖旧内容。只读到标题不能声称重复，查询失败不当作没有重复。GitHub 仍须独立检查是否缺失，不在此提前结束整个主流程。
5. **图片属于必须执行的归档步骤**：先阅读 [图片上传、插入与验证流程](references/images.md)，处理用户图片与助手配图。能取得原文件时实际上传，不能停在登记文件名。若有可点击、拖动读数或修改参数的函数图表，另读 [交互图表原生 HTML 归档](references/interactive-charts.md)：优先取真实 HTML/数据并使用原生 `<embed>` 保留交互，不以 PNG 或截图代替。只有截图时保存截图并标缺交互源，不能冒称已迁移程序。普通图片继续按现有文件 POST/SVG 路径保存，缺原文件或传输能力时精确报告。
6. 按原图模板的三栏主体、底部两栏及原生配色保存正文，完整讲解和原始问答过长时用全宽区/专题子页。将已上传图片与交互图放在对应知识点后，再回读逐条核对原问题、原回答、追问链、推导步骤与例题，不能只检查标题。另核对两类实际图片块、分栏、颜色、目录、截断/未知块、课程父级、日期目录/专题链接，以及公式的宽度检查和合适字号、代入与结果的独立块、计算后的换段及结果框。原文、问答、步骤或媒体有缺失时报告“部分完成”。结果不确定先查状态，避免重复上传或重复建页；只重试已明确失败的缺失部分一次，仍失败则报告具体阶段与补传位置。

只写本次笔记和已识别的插件笔记；不删除、不搬移现有课程、数据库或人工笔记。引用现有页面用 mention/link，不能用可能移动页面的 `<page>` 或 `<database url>` 代替引用。

## 交付

返回真实页面链接、课程归属、覆盖范围，以及“用户图片 N/M；助手示意图 N/M”的独立完成数。只有上传完成、已插入且回读验证的图片计入已保存数；有缺图时首段标“部分完成”并列出具体补传办法。用户要求补图时读取原笔记并原位补入，保留已有全文。连接不可用时交付草稿并说明待连接，不谎称保存成功。

同时返回来源可读范围、真实学习日期或待核实状态、原问题/原回答/追问链/例题的覆盖数和未解决问题。早期原文不可读时明确“基于当前可访问内容，非全文完整归档”；旧笔记未按本标准复核，不称已补齐。

存在交互图表时，另外报告源文件取得数、HTML 已嵌入数、实际交互验证数及 GitHub 源文件备份结果。只回读到 `<embed>` 不等于已测试点击/拖动，更不等于 iPhone 实测；缺原交互源或只保存静态截图时明确标注。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](../study-chat-notes/references/history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。

## 相同内容只保存一次

完整保留原文与去重同时执行：已在目标中完整保存的相同问答、解释、图片和交互源不再重复上传，补传历史和同批次重复也一样。全部重复时不新建页面/文件、不刷新日期、不生成补充报告或提交，直接返回已有链接并报告“重复跳过”。部分重复时只补新增或缺失部分，重复原文引用已验证完整位置；不能改标题或加后缀重存整篇旧内容。不同追问、不同答案、缺失全文/步骤/媒体仍须补齐。Notion 与 GitHub 分别核对，只补缺失目标；不自动清理历史重复笔记。
