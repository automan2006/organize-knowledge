# 可视化卡片默认双端归档

正式整理时，可视化卡片属于必须盘点的学习内容，不需要用户再说一次“上传卡片”。遵守已选目标与内容范围，默认保存 Notion 和 GitHub。包括概念对比卡、示意卡、信息图、流程图、SVG/Canvas 图解、可交互函数、计算器、滑块、参数面板、可视化表格及聊天旁的可视化产物。静态 HTML 卡片也需要保存源文件；没有点击或拖动功能并不构成忽略它的理由。普通图片仍保存原件，不伪称具有 HTML 源。仅讨论或升级插件时不归档本聊天和示例图片。

## 逐项识别与取得

对选中聊天范围内的卡片逐一记录标题、关联知识点、来源消息/真实产物、来源形式、已有交互、源文件可访问程度及依赖。按实际宿主能力读取原产物或文件，不能把界面中的不可读引用当作源码。截图不能证明原卡片是否可交互。用户给出的“无基准要求/有基准要求”卡片截图是类型示例；本次只升级功能，不从图中编造原程序。

已有 HTML 则保留原字节及 SHA-256；数据嵌在 HTML/JS 内时连同源文件保存，无需虚构另一个 data.json。独立 JSON/CSV/数据文件、JS、CSS、SVG/字体等实际依赖同时盘点和保存，保留原相对路径与模块关系。保留真实公式、曲线数据、参数范围/单位、默认值及事件处理、重绘、重置、切换逻辑；不能只存最终截图或界面文字。没有交互的卡片标 static，不添加不存在的控件或测试结论。

原产物为 React/TSX、Canvas 或宿主组件时，尽可能保留真实源、数据与配置；具备源码和导出能力时迁移为完整 HTML，标 ported 并记录封装差异。原源与迁移 HTML 分开保留，不能把重新编写的版本称为原件。依赖宿主 API、外部请求、CDN、模块构建或授权的数据需逐项核实，不能把“保存了 JS”当作可脱离宿主运行。缺源码/依赖时明确指出卡片及缺失文件，不自行按截图重建；用户要求重建时另标 reconstructed。

## 保存 Notion

执行 [HTML 上传与交互验证](interactive-charts.md)。把完整 HTML 通过当前连接的真实文件上传接口保存，用实际返回的来源建立原生 embed，放在对应知识点旁；复杂卡片放全宽区，支持移动端纵向阅读。独立数据和逻辑原件同时作为文件附件提供，或保存可取得的完整资源包以供下载；文件包下载不等于其中的相对资源已在 Notion embed 内可加载。单文件迁移需将可取得的资源正确内联，保留原件和迁移来源记录。不要将源码代码块或截图说成可视化卡片已嵌入。

逐文件核对上传、页面绑定/挂载与回读，支持时核对哈希。使用当前工具 schema 的真实文件类型及限制；当前工具无法上传某种源文件时保留本地文件，继续可完成的目标并报告缺口，不能把文件名/临时地址当已保存原件。完成笔记保存后仍执行 [主页底部链接](homepage-note-links.md)。

## 保存 GitHub 与 Markdown

在已核实的私人笔记仓库、该笔记实际所属的课程/知识/书籍分类目录内保存 `assets/visualizations/<资源包内容指纹>/`。指纹覆盖实际文件清单、相对路径和每个文件的真实内容哈希，不能只比较截图或 HTML 而漏掉变化的数据/逻辑。原文件目录结构保留，原源与迁移产物用独立子目录区别。一个卡片包含多文件时记录实际入口、各文件 SHA-256、来源类型和已知依赖缺口；不要将凭据或宿主授权配置混入导出文件。

先读目标资产及内容再创建，不覆盖已有文件；完全重复复用原包。对每个新增文件通过实际可用工具保存并按真实 commit 回读验证，不能只提交 HTML 而宣称数据和逻辑也上传了。现有 archive_github_notes.py 仅处理 Markdown，archive_github_assets.py 仅处理其声明的图片/PDF；不要给它们传 HTML/JS 并声称支持。UTF-8 源使用可用连接器/认证 CLI 的文件创建接口，二进制依赖使用支持原字节的接口；没有工具则报告未上传。

Obsidian Markdown 在相关知识点后链接实际存在的入口 HTML、数据与逻辑文件，保留 YAML、公式及 related_candidates。私有 GitHub blob/raw 链接不能当可执行托管网站；普通 Markdown 链接只提供打开文件入口。不能声称已同步到本地 Obsidian 或笔记内自动执行。GitHub 仍追加新笔记/增补文件，不覆盖旧笔记。

## 去重、验证与回执

Notion 和 GitHub 分别对比正文、卡片源、数据、逻辑、参数及依赖。文字相同但卡片未存、只有截图、数据或逻辑有新增时，只补缺失部分；相同资源在同批次/多篇笔记间复用，不因改名或临时 URL 变化重复上传。全部重复仍不写页面/文件或空提交。旧卡片未存的情况只在本次选中范围内补齐，不因插件更新扫描或重写所有旧笔记。

分别报告：应保存/取得源的卡片数、HTML 已上传/已嵌入数、数据和逻辑文件实际路径及提交、各目标重复跳过项、依赖缺口、回读哈希状态。交互卡片有预览能力时实际测试原有点击、拖动、改参和重置；静态卡片检查渲染。未做执行测试标“已保存，运行未实测”，iPhone 触摸验证单列；仅有截图标“静态图已保存，原 HTML/数据/交互逻辑缺失”。一端或部分文件失败时报告部分完成，不把文档更新、代码存在或截图存在当运行成功。
