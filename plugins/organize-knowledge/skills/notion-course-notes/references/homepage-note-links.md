# 每篇笔记保存后，在所属主页底部登记链接

这是正式归档的必要导航步骤，适用于课堂、知识、读书笔记及新增的补充笔记；仅预览、只导出或明确只保存 GitHub 时不执行。每写完并上传一篇 Notion 笔记，就处理该篇链接，不等整批结束。仅更新插件不归档聊天、不补写历史主页。

## 位置与外观

- 课堂：在已确认的课程主页底部、原有上课记录数据库或既有内容下方添加。即使专题放在日期目录子页中，也应在课程主页提供直达专题的链接，不能只链接日期总目录。
- 知识：在所属领域分类主页底部添加。
- 读书笔记和阅读聊天：在对应书籍主页底部添加；书籍归属沿用已核实分类。
- 一篇笔记对应一行，使用 Notion 原生页面 mention/link-to-page 或普通标题超链接，表现为可点击的页面标题，类似用户截图中的列表。支持时显示实际笔记图标。优先沿用现有底部笔记链接区；没有时追加简洁的“学习笔记”标题和链接区，不重排数据库或人工内容。
- 显示笔记真实标题；有已核实学习日期时可显示“日期｜标题”，日期未知则只显示标题。使用真实页面 ID/URL，不能伪造或用示例链接占位。需要显示外部链接时遵守当前 Notion Markdown 规范。

## 逐篇执行

1. 保存笔记，取得真实页面 ID/URL 并回读正文，确认这一篇已保存。未保存或结果未知时不添加悬空链接。GitHub 结果独立核实，GitHub 失败不阻止已成功的 Notion 笔记被索引。
2. 读取该笔记所属的已确认主页及底部已有链接。必须覆盖全部底部链接、折叠区和分段/分页结果，不能只看标题或截图。按目标页面 ID 去重：统一带/不带连字符 ID、不同 Notion 域名、slug、查询参数和锚点，不以标题相同判重复。同批次记录已加入 ID，避免再次插入。
3. 已有指向该页面的链接则跳过，保留原显示名称；同标题但不同页面按真实目标分别处理。只有主页其他区域已有父子层级引用、不存在底部导航时，新增本次笔记的底部导航是允许的，但不移动原页面。
4. 没有链接时，用当前连接支持的局部插入/末尾追加操作增加一行，保留主页正文、数据库、分栏及人工内容。只创建链接引用，不使用可能移动/创建子页面的 page 或 database 标签。不得通过全文替换实现简单追加。
5. 写入后重新读取主页，验证底部导航链接指向该篇正确页面。超时/结果不明先回读确认，不能直接重试制造重复；如仍无法确认，报告“主页链接待核实”。只有明确未写入且再次去重后才重试。
6. 笔记已保存但主页权限不足、位置不明确、检索不完整或链接添加失败时，保留已保存笔记，返回真实链接并单列“笔记已保存；主页链接未完成/待核实”。不把导航失败说成笔记保存失败，不重复创建笔记来重试链接。用户要求重试本次未完成导航时，只修复已确认那一项。

## 与去重和交付的关系

完整重复的旧笔记继续跳过，不为了这次升级批量给历史笔记补链接，不更新其正文或日期。只有本次实际新建/增补并保存的笔记执行此流程；原位新增内容仍指向原页面，已有导航不再添加。用户另行明确要求补齐旧导航时，可在指定范围按页 ID 去重后补链接。

逐篇回执同时给出笔记真实链接、所属主页链接与导航状态“已添加并回读验证 / 已存在，跳过 / 未完成 / 待核实”；一篇完成就可在聊天进度中给链接，最终再汇总。不能只在聊天发链接却称 Notion 主页已登记，也不能把文件上传回执当成页面导航已完成。
