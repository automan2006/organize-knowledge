# 课堂检测、错题与薄弱点归档

仅本学期课堂笔记正式整理完成后默认出题，或用户明确要求课堂检测时使用。独立识别手写、课外知识、读书笔记、预览、升级插件不自动出题。用户说“这次不测试”则跳过。课堂笔记完整重复且已验证保存时仍可提供本轮检测，不为此重存旧笔记；同轮已经出题则继续现有试卷，不重复生成。

## 1. 确认课堂并出题

先完成原课堂笔记整理并报告真实保存状态；一端归档失败不阻止基于已核实内容检测，分别报告未完成保存项，不把尚未整理说成整理完成。确认实际课程、课堂日期（未知标待核实）、主题、原笔记链接/路径、所选保存目标及可读来源。多堂课混合时询问检测哪一堂，继续已有笔记归档，不擅自混卷或每堂同时出一套。仅含插件功能讨论时不出题。

基于这堂课已核实的概念、方法和例题，选覆盖核心考点的一套五题：Q1/Q2 概念题各15分、各1分钟；Q3 辨析题20分、2分钟；Q4/Q5 应用题各25分、各3分钟。总计100分、预计10分钟。非计算课程改用解释、案例分析或操作题，题数与分值不变。首次出题前选定且注明两道核心题，不按作答结果修改核心题身份。来源不足或公式仍待确认时避开该考点；不足以构成有效检测时说明缺口，先补齐，不能编造确定答案。

每题显示题号、分值、预计用时、考查点及是否核心题，不显示答案、解析或评分细则。准备完整题目和来源、合理答案、步骤评分依据；答案仅在批改阶段生成/交付，不把隐藏答案上传到任何可见文件、折叠块、HTML 或元数据。题目提供必要已知条件，不从缺失原图猜数值。无须等待十分钟或创建提醒，建议用户自己计时，不自动计时、不强制交卷。

用稳定 quiz_id 关联本套题与后续记录，同卷换标题不更换编号；默认轮次为1。给出“按题号提交；答完后说交卷，也可以分次作答”。题目、核心题、条件一旦发出保持不变，发现歧义则公开更正并记录，不能暗改答案标准。

## 2. 等待作答与批改

同一聊天保留每题用户原始回答和先后更正。部分作答只确认收到哪些题、还缺哪些题，不提前批改或泄露答案；五题都提交或用户明确说交卷后统一批改。用户主动要求某题帮助时提供所需帮助并标“使用提示”，该题不能作为独立掌握证据。用户要求提前看答案时遵从并注明该题已泄题，不宣称独立达标。

手写答案先经 [手写识别](../handwritten-notes-ocr/SKILL.md)，保留原图、页码/区域和转写。不确定字迹标待确认，确认前不计错、不做最终评分；测试可停在待确认状态。未明确交卷时空题不计零；明确交卷后仍空白的题计零分，标“未作答／尚未验证”，不直接断言不会。

接受等价正确表达，按知识与过程给部分分；计算题分别核对方法、代入、结果、单位。不机械匹配字面答案，不因写法不同扣分。数学验算与来源核对后给每题得分、依据、标准答案和逐步解析，保留用户原答，不把纠正后的答案冒充原答。

总分至少80分、两道核心题各达到本题满分的80%、且没有关键概念/方法错误，才称“本次检测达标”。有提示/泄题则另标“辅助完成，独立掌握尚未验证”，不按独立达标报告。未检测的知识点明确列“未覆盖”；一次检测不等于这堂课全部知识永久掌握。可选使用 [评分辅助程序](scripts/assessment.py) 校验分数、交卷状态及核心门槛；它不理解学科、不判断答案正确性，也不负责上传。

逐题分为“本题通过／部分掌握／答错／未作答／待确认”。错因区分概念、方法、步骤、计算、单位和表达，必须有本次回答证据。对错题给出错误具体位置、正确方法、补学讲解、原课堂笔记真实定位及一个有针对性的练习建议。没有错题也保存整套检测，写“本次未发现错题”及未覆盖考点，不制造薄弱点。

## 3. 完整记录与两端归档

本轮正常课堂整理已授权的保存目标继续用于交卷后的检测记录，默认 Notion+GitHub，不再要求重复上传指令。明确只选一端则只保存该端；只练习/不保存则只聊天反馈，独立调用本 Skill 时遵守用户所说的练习或保存范围。交卷前不把未完成考试或答案自动写入课程；中断后如用户要求保存进度，仅保存题目、已提交答案及未完成状态，不附答案，不伪造成绩。

记录课堂及检测日期（真实已知值）、quiz_id、轮次、来源课堂链接、所选目标、全部题目、用户原答和更正、逐题评分、标准答案及解析、核心题门槛、总分、达标依据、错题与薄弱点、尚未验证项和未覆盖点。保留图片/手写答案及可视化资源规则。测试未完成或字迹待确认时不创建最终批改记录。

Notion：同课程、同课堂日期目录下创建“课堂检测｜主题｜第N轮”完整记录，按现有学术模板突出答案解析、公式和错因。关联课堂笔记、必要的补学专题；保存后执行 [主页底部链接](../notion-course-notes/references/homepage-note-links.md)。日期未知沿用原笔记的待核实目录，不以检测当天冒充上课日期。

GitHub：同课程真实目录下的 `课堂检测/`，文件名“课堂日期-主题-第N轮-检测记录.md”（日期未知用“课堂日期待核实”）。保留既有 YAML、公式及 related_candidates，可增 quiz_id、attempt、assessment_status、lesson_date、assessment_date、score 和来源路径。明确复用已验证课程路径后，把该子目录作为分类 existing_path 传给 Markdown 归档助手；不要让分类默认路由误放到课程根目录。标题不含路径分隔符，沿用目录安全检查。

两端分别按 quiz_id、轮次、原答、评分与解析核对实际内容：同卷同记录完全重复跳过，不产生空提交；同一用户真实更改答案、修订批改或复测有新增时写增补记录，保留原成绩与证据。GitHub 只追加，不覆盖旧文件。Notion 可按已识别区域增补并保留人工内容，不能可靠定位则建关联增补页。无外部写权限或一端失败，先交付批改结果和待上传 Markdown，完成另一已选目标，列出真实路径/链接、提交及回读状态。不得声称待上传已同步。

## 4. 复测与恢复

批改结束提供“复测薄弱点”入口，用户选择继续才出新题，不自动无限考试。生成测同一核心方法、条件或表达而非照抄原题的新五题十分钟试卷；聚焦本轮薄弱点，其余题验证关联前提。无薄弱点时只在用户要求下做拓展检测。复测使用新的 quiz_id、attempt 加1、parent_quiz_id 指向前轮，重新预定两道核心题，独立记分，不能把复测成绩覆盖或混加到首次成绩。

中断仅表示待继续，不虚构作答或完成。换聊天时先实际读取已存记录或用户提供的试卷/回答，核实题目、核心题和轮次；无可读依据时明确无法恢复，不凭记忆补造。继续和上传重试复用原 quiz_id；没有新答案或新批改不创建重复记录。
