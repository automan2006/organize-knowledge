# Obsidian 概念笔记导出

先按 [任务选择规则](../study-chat-notes/references/task-selection.md) 确定目标和内容范围。Organize knowledge 正常主流程默认保存 Notion + GitHub，并保留可复制 Markdown 交付，本 Skill 为其生成完整笔记并执行下方私有归档。单独点名本 Skill 或明确要求“只给 Obsidian”时，执行独立导出，不自动写入其他目标；用户限定只保存、不贴正文时只交付其指定结果。

按 [知识提取规则](../study-chat-notes/references/extraction.md) 建立所选范围内完整的知识清单。不操作本地 Obsidian 库，不安装或配置其插件。只要求 GitHub 保存时，可生成必要的 Markdown 文件并返回路径/提交，不自动在聊天中附所有笔记全文。

所有科目均执行 [完整学习档案标准](../study-chat-notes/references/complete-learning-archive.md)。建立学习记录与概念笔记两类内容：真实日期的学习记录保留原始问题、助手可见原回答全文及连续追问顺序；稳定命名的概念/方法/例题笔记保留完整解释，并定位与之有关的原始问答。也可将问答全文存于概念笔记，但不能两处都只留摘要或只给不可访问聊天链接。已知日期分别归档，未知标待核实，不能用归档日期补造学习日期。

## 与 Notion 的区别

Notion 是课程顺序的完整专题长文，Obsidian 是可独立理解、可复用和可关联的概念网络。保持知识覆盖与解释完整，但重新组织，不直接复制 Notion 正文，不以“原子化”为由删掉条件、证明、例子或错误纠正。

- 一个核心概念一篇；相互依赖且拆开会破坏理解的内容保持在一起。完整长例题可独立成例题笔记，概念笔记说明其作用。
- 先输出课程/主题目录和有真实日期依据的学习记录，再输出各概念/公式/方法/例题笔记。学习记录按学习日期区分，概念网络跨日期联系，不按日期重复制造同一概念。每篇外面标注建议文件名，正文放独立可复制的 Markdown 代码块；正文有三反引号代码时用四个或更多反引号包住。
- 文件名用清楚稳定的中文概念名，同名跨学科时加入学科限定；去掉 Windows 不支持的文件名字符。不要用日期作为概念名称主体。
- YAML frontmatter 包含 `title`、`aliases`、`tags`、`type`、`course`、`source`；只记录真实已知来源。日期使用用户已确认的时区，无法确定时不伪造日期。各概念增加 `related_candidates`（纯字符串列表），它只是候选关系，正式链接由用户插件生成。
- 正文保留“一句话解释 → 定义与边界 → 完整推导/工作原理 → 完整例题/应用 → 原始问答或其真实归档定位 → 易错点与纠错 → 由真实疑问生成的自测及解析位置 → 相关概念及关系原因 → 来源”。计算逐步保留代入、每步依据、结果与判断；图片放在相关知识/例题处。内容不适用的模块不硬凑。
- 候选关系应有理由，如前置知识、推导依据、对比概念或应用，不用大量无意义标签制造关系。不假装知道用户整个 Obsidian 库有哪些笔记。
- 默认不预写 `[[概念]]` 双向链接；用户已经选择由后续插件生成。图片嵌入语法不属于概念双向链接，但只有实际交付图片文件时才写 `![[assets/...]]`。图处理遵循 [图片流程](../notion-course-notes/references/images.md)。
- 可交互函数图表按 [HTML 归档](../notion-course-notes/references/interactive-charts.md) 保留实际源文件和数据；Markdown 附已交付 HTML 的真实相对链接、公式与参数说明。正文/代码块本身不自动变成交互控件，不把 Notion 临时附件 URL 当永久 HTML 路径。

## 输出样式

标注 `建议文件名：尺寸公差.md`，随后提供可复制块，例如：

````markdown
---
title: "尺寸公差"
aliases: ["公差宽度"]
tags: ["机械工程", "互换性与技术测量"]
type: "concept"
course: "互换性与技术测量"
source: "当前聊天：关于尺寸公差的提问"
related_candidates: ["上偏差", "下偏差", "公差带"]
---
# 尺寸公差

按本次实际聊天写完整正文，不照抄示例。

## 相关概念与关系

- 上偏差、下偏差：用于计算公差宽度；具体条件在正文说明。
````

选中了 Obsidian 聊天导出时，有文件生成能力可另交付 `.md` 和图片包，但仍提供用户可直接复制的正文，不只给下载链接。内容超长则标明总批次和每批笔记清单，明确尚未交付部分。不要把临时链接作为永久图片路径。

## GitHub 私有归档

**主流程正常默认启用本节**；用户只选其他目标、排除 GitHub 或单独调用 Obsidian 导出时跳过。根据最终目标清单执行仓库读取、分类与提交，不在用户排除 GitHub 时检查连接或报告待上传。

启用后，先读取 [课程与领域分类](references/classification.md)，根据内容及 Notion 实际课程归属选择分类，再生成含真实分类信息的最终 Markdown。查询已有 GitHub 目录与相关 YAML：同一 Notion 课程统一放在同一目录，已有领域复用，新的方面才新建领域；课程无法核实时不能假装它是新领域。

再读取 [目标配置](references/github-config.md) 和 [创建、冲突保护及提交验证](references/github-archive.md)。将用户本次选中上传的每篇笔记原样保存为独立 `.md` 文件；直接上传笔记正文，不包含聊天外层代码围栏或“建议文件名”说明。保留 YAML、公式反斜杠、代码与 `related_candidates`，不能为了上传而压缩或重写。

写入前先按 [重复检查](../study-chat-notes/references/deduplication.md) 比较同分类旧笔记：完整覆盖包括原始问答、追问、推导/计算中间步骤与媒体，不能因已有公式或主题相同跳过新增学习过程。同名或不同名且内容完整重复时跳过提交，返回原路径；不能通过新日期或后缀生成重复副本。只有内容有新增的同名笔记才创建带后缀的新版本；不得传现有文件 SHA 去更新、覆盖、删除、重命名或强制推送。仅使用已授权私有仓库，不以公开源码仓库替代。

每篇返回分类、已有或新建路径、新增/重复跳过状态和验证依据。新建项需真实提交与回读；跳过项返回已有链接并明确“本次无新提交”，不伪造 SHA。无法比较或上传时说明并保留可恢复文件；聊天导出仍按任务选择交付。GitHub 保存不等于本地 Obsidian 已拉取或已生成双向链接。

## 原文全文保留与历史补齐

必须执行 [原文缺口定位、历史补传与增量补充](../study-chat-notes/references/history-backfill.md)。所选聊天范围内用户消息和助手可见回答默认按顺序保留全文，包括铺垫、重复解释和寒暄，不精简、改写或只选重点；整理层之外保留可定位的原文层，长文分片并逐片回读。知识点语义重复不能替代原文覆盖检查。无法访问的内容逐段列出已知对话标题、日期、可见前后文、缺失类型和本次缺口编号；没有定位依据时直说无法确定哪段及缺失条数，不能编造。

用户补传历史并要求补齐时，读取文件与旧笔记全文，按原文、知识点、追问、步骤、纠错和媒体分别比较，补存遗漏并列出新增知识。Notion 补入已识别区域或创建关联增补页；GitHub 追加新文件，保留 YAML、公式与 related_candidates，不覆盖旧文件。每个缺口按目标保存状态核对，验证后才标已补齐；完整重复继续跳过。返回已补齐和仍缺的具体段落、所需补传范围及实际保存结果。默认两处保存，用户明确限制时遵从；单纯上传附件不自动写入，只有要求补齐/整理时执行；只对比不上传则交付差异清单。只更新插件不归档本次聊天。

## 相同内容只保存一次

完整保留原文与去重同时执行：已在目标中完整保存的相同问答、解释、图片和交互源不再重复上传，补传历史和同批次重复也一样。全部重复时不新建页面/文件、不刷新日期、不生成补充报告或提交，直接返回已有链接并报告“重复跳过”。部分重复时只补新增或缺失部分，重复原文引用已验证完整位置；不能改标题或加后缀重存整篇旧内容。不同追问、不同答案、缺失全文/步骤/媒体仍须补齐。Notion 与 GitHub 分别核对，只补缺失目标；不自动清理历史重复笔记。
