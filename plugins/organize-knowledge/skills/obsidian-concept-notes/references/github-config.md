# 使用者的 GitHub 私有归档配置

正常整理默认同时保存 Notion + GitHub，并保留可复制 Markdown 交付；用户明确限制时按 [任务选择规则](../../study-chat-notes/references/task-selection.md) 执行。公开版不预设作者的私人笔记仓库，首次使用须由使用者指定自己的私有仓库（`owner/repo`）并授权。没有配置时继续完成可执行的 Notion 与 Markdown 交付，说明 GitHub 尚未配置，不将笔记上传到本插件的公开源码仓库。

- 仓库：使用者提供的私有仓库；运行时核实 private 与写入权限。
- 分支：读取真实默认分支；指定其他分支时先验证它存在。
- 分类规则：执行 [课程与领域分类](classification.md)，优先沿用 Notion 已确认课程，复用 GitHub 已有分类，新的方面才新建领域。
- 默认路径：课程为 `课程/<真实课程名>/<概念或例题名>.md`，非课程领域为 `领域/<稳定领域名>/<概念或例题名>.md`。已有分类路径优先，目录笔记也单独保存。
- 去重与同名策略：先执行 [重复检查](../../study-chat-notes/references/deduplication.md)，知识完整重复时不创建文件或提交；只有内容有新增的同名笔记才加 `--时间-内容指纹`，仍冲突则加序号。`title` 与 `related_candidates` 保留概念名，原文件不覆盖。
- 授权：完成自己的账号和位置配置后，正常调用整理按两处保存默认执行，只新建本次笔记；明确限定目标/范围时仅操作对应部分，只更新插件、预览或独立导出时不写入。

仅保存本次笔记，不上传整个目录、聊天原始导出、凭据和无关资料。不修改已有文件，不创建/改变仓库可见性，不自动安装本地 Obsidian 同步插件。使用自己的 GitHub 连接或已认证 `gh`，不在聊天、文件或日志中放入令牌。
