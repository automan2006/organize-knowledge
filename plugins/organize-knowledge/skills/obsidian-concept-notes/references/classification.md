# 识别内容并复用课程或领域分类

正常整理默认同时保存 Notion + GitHub，在生成 GitHub 目标路径前读取本文件。用户明确排除 GitHub 或仅执行独立导出时跳过本流程，不为分类而读取仓库。只处理本次所选笔记，以其实质内容和 Notion 已核实的课程归属为依据；不是按当天日期、聊天标题或单个关键词分文件夹。

## 先看 Notion，再看仓库

1. 完整流程使用 Notion 归档步骤已确认的**课程页面 ID、真实课程名称、页面链接**作为首选分类。若是在整理现有 Notion 笔记，读取其父级/关联课程，不能把普通专题子页误认成课程。独立导出 Obsidian 时，查询配置的现有课程库，结合知识点内容匹配课程；不能只凭“机械”“代码”等词认定归属。
2. 列出 GitHub 默认分支中的现有目录，并读取相关课程目录下笔记的 YAML；忽略 `_tests`、回执、附件和临时目录。优先使用 `notion_course_id` 对应的已有分类；再核对真实课程名、课程链接和现有别名。不需要读取所有无关笔记正文。递归树被截断时继续读取相关子树，不能把未返回的分类当作不存在。
3. 同一个 Notion 课程的目录、概念、公式、方法和例题统一放入同一 GitHub 课程目录。已有分类路径即使与默认路径不同也复用，不另造同义目录。课程改名但页面 ID 不变时继续复用原目录；不同课程仅名称相同不能合并。若多个旧目录实际指向同一课程，按证据选定一个后续归档目录并报告，不自动搬移、删除或合并旧文件。

## 课程与新领域的路径

- **已有课程分类**：复用查到的路径，例如 `课程/机械设计/螺栓连接.md`。这门课后续的“轴的强度”“齿轮传动”仍进该目录，不为每次聊天建立新分类。
- **Notion 有这门课，但 GitHub 尚无分类**：自动建立 `课程/<真实课程名>/`，第一次创建 `.md` 时目录随之形成，不需要占位文件。同名不同课程用稳定课程标识后缀区分。
- **确实不属于现有课程的新领域**：先按内容选择稳定、适度宽泛的领域名，例如“Python 编程”“英语学习”。先查询已有领域是否同义或相关：有则复用 `领域/<已有领域>/`，确为新方面才创建 `领域/<新领域>/`。不要把每个具体知识点都升级为新领域，也不把领域塞进不相关课程。
- **跨课程/跨领域**：逐篇判定；目录笔记按课程/领域分别生成，不能把整条聊天强制归到第一门课。一个共享概念选最贴合本次用途的主分类，其他归属在候选关联与正文中说明，不无端复制多份。
- **课程未查到与查询失败不同**：Notion 连接失败、查询不完整、多候选或无法确认归属时，不能宣称“新的方面”并创建永久领域。已有可靠课程 ID 与目录映射可继续复用；否则先交付 Markdown 并标注“分类待核实、尚未上传”，只询问影响该笔记的归属，其他明确笔记继续。

启用 GitHub 保存后才执行这些分类规则。**不自动在 Notion 课程库中新建课程或修改数据库结构**；用户同时选择 Notion 时，新领域的保存位置继续遵循原归档配置，没有可用位置时只说明待指定，不编造课程。不能因为 Notion 缺少某领域而阻止已明确选择并分类的 GitHub 笔记交付。

## 保存依据，供下次复用

导出时在原有 YAML 字段外增加真实分类信息：`category_kind`（`course` 或 `domain`）、`category`（真实课程/领域名）、`category_path`（最终目录）。课程笔记再增加真实 `notion_course_id`、`notion_course_url`；未实际取得的字段不伪造。课程 ID 指课程页面，不是课程库 ID 或本次笔记子页 ID。

这些字段在生成最终 Markdown 时确定，然后原样上传；不破坏 `title`、`aliases`、`course`、公式、`related_candidates` 和已有正文。领域笔记不伪造课程，可将 `course` 记为 `null`。别名的语义匹配由模型根据目录、YAML 和内容做出，不能假装辅助程序自身理解了学科内容。

提交结果除文件路径、提交 SHA 和验证状态外，报告每篇**分类名称、复用/新建、依据**。尚未成功提交的目录称“拟创建”，不能仅规划路径就称已建分类。

## 有终端时的路径辅助

[archive_github_notes.py](../scripts/archive_github_notes.py) 支持在清单每一项中使用 `filename` 与 `classification`，由已核实的分类决定目录。示例中的课程 ID 是占位说明，运行时必须替换为真实查询结果：

```json
{
  "repository": "owner/private-notes",
  "files": [
    {
      "file": "output/螺栓连接.md",
      "filename": "螺栓连接.md",
      "classification": {
        "kind": "course",
        "name": "机械设计",
        "notion_course_id": "从 Notion 读取的真实课程页面 ID",
        "existing_path": "课程/机械设计",
        "reason": "本次 Notion 笔记实际归档在该课程下，仓库已有对应目录"
      }
    },
    {
      "file": "output/列表推导式.md",
      "filename": "列表推导式.md",
      "classification": {
        "kind": "domain",
        "name": "Python 编程",
        "course_status": "no_match",
        "reason": "已核实不属于现有课程，也没有同义领域目录"
      }
    }
  ]
}
```

`existing_path` 仅在实时读取仓库确认已有目录后填写；新分类省略它。程序将同一课程 ID 的各篇放在同一目录、支持复用旧目录，并阻止路径与分类不一致；它不查询 Notion、不做语义判断，也不修改 YAML 或搬移旧文件。无终端时，按同样规则选择路径，再用 GitHub 创建文件工具归档。
