# Markdown 创建与提交核实

执行前按 [任务选择规则](../../study-chat-notes/references/task-selection.md) 确认本次目标。正常整理默认同时保存 Notion + GitHub；用户明确排除 GitHub 或仅执行独立导出时跳过本流程，包括仓库读取与连接检查。只处理用户限定的笔记范围，未限定时保存本次全部 Markdown。

## 先核实目标与能力

读取配置，实际查询仓库元数据，确认正确仓库、private/visibility=private、真实默认分支及写入权限。GitHub 不可连接、仓库不可见、权限不足或可见性不是私有时停止 GitHub 写入，保留待上传 Markdown 文件，继续其他已选任务；不能自动改投公开仓库、创建新仓库或要求用户在聊天中粘贴令牌。

优先使用宿主已连接的 GitHub 工具，适合手机、Windows 与网页；工具列表可见不代表有写权限，按实际工具返回执行。没有可用连接时才使用已认证的 GitHub CLI 辅助程序。无终端不应阻止可用的连接器路径；没有任何写入能力时如实报告尚未上传。

## 一篇一文件，只创建

先按 [课程与领域分类](classification.md) 读取 Notion 归属及 GitHub 已有目录，为每篇确定可复用的课程/领域目录，随后执行以下上传流程。同一课程合并在同一目录，确为新领域才新建分类；不要根据单条聊天标题直接建目录。

1. 建立本次**选中上传范围**的笔记清单，包含该范围适用的目录、概念、公式、方法、例题；每篇对应独立文件，不只上传第一篇或合并成摘要，也不将用户没选中的笔记一起上传。
2. 按已核实的分类选择课程或领域的相对路径，去掉 Windows 不支持的字符与保留名，拒绝绝对路径、`..`、`.git` 等。保留正文 UTF-8、YAML frontmatter、美元符号、LaTeX 反斜杠、换行与候选关系。代码块的外层围栏不属于文件正文；嵌套代码围栏需要保留。
3. 按 [重复检查](../../study-chat-notes/references/deduplication.md) 读取同分类候选全文：同名或不同名但内容等价且无新增时直接跳过，不创建文件或提交。只有内容有新增且文件同名时另取后缀；已有目录占用该路径也需改名。保留旧笔记和人工内容，可列目录避免 Windows 大小写冲突。后缀不改变概念标题及候选关联。
4. 逐篇、顺序调用 GitHub **创建文件**工具，传完整正文、目标分支和提交说明。REST Contents API 使用 Base64 原字节且**不传 `sha`**；不得使用更新文件、删除、强制推送，也不得把空 SHA 当成覆盖许可。API 在同名路径出现时应拒绝写入；冲突后重新查目标，再为新文件选名。
5. 请求超时或响应不确定时，先检查同一候选路径和对应提交；不能直接改名再上传而造成重复副本。明确的同名竞争可换名，最多重试两次；其他权限/连接错误停止受影响部分。脚本的 100 次命名上限只是避免命名空间耗尽，非重试失败网络请求 100 次。

目录笔记保留完整候选关联；默认仍不生成概念双向链接。Notion 也被选中时图片继续走原有上传、插入和回读流程；本次 GitHub 新增的是 `.md` 文件，不把临时 Notion/ChatGPT 图片地址宣称为永久 Obsidian 附件。只有用户要求且实际交付到库中的图片才使用本地嵌入路径。

## 两种执行方式

### 交互图表源文件

当前 Markdown 辅助程序只接收 `.md`。交互图表的真实 HTML/数据按 [交互图表流程](../../notion-course-notes/references/interactive-charts.md) 作为关联资产另行保存；先比对已有同哈希路径的实际内容，相同则跳过，新增才调用可用的 UTF-8 文件创建工具，并回读验证。不要将 HTML 强行改成 `.md`、仅把路径写入正文而不上传文件，或把私有仓库源文件链接当成 Notion 可执行网站。

### GitHub 连接器

查询仓库后，用当前 schema 中的取文件/创建文件/取提交工具（例如 `fetch_file`、`create_file`、`fetch_commit`），不猜参数。创建返回的真实提交 SHA 必须保留；随后以这个 SHA 作为 `ref` 回读文件，比较完整正文，并读取对应提交确认它包含此路径。工具若只返回文本内容而非二进制，至少完整比较 YAML、公式及换行；支持 Base64 时以原字节/真实哈希核对。404 只有在仓库与分支已核实可访问时才能当作文件不存在；403/网络异常不可当作不存在。

### 已认证的 CLI 与 Python 3.9+

可用 [archive_github_notes.py](../scripts/archive_github_notes.py)，它使用 `gh api`，不读取或打印令牌，不变更笔记正文。自动分类归档优先使用 [分类清单格式](classification.md) 中的 `filename` 与 `classification`。明确指定路径或测试流程仍兼容以下 JSON 清单：

```json
{
  "repository": "owner/private-notes",
  "files": [
    {"file": "output/尺寸公差.md", "path": "课程/互换性与技术测量/尺寸公差.md"},
    {"file": "output/课程索引.md", "path": "课程/互换性与技术测量/课程索引.md"}
  ]
}
```

```sh
python archive_github_notes.py --manifest notes-manifest.json --receipt upload-result.json
```

每个需写入的正文按原字节上传，不重新序列化 YAML、不改公式。程序读取目标分类中的 Markdown 并计算去重指纹，同内容跳过，同批次也去重；仅有新增的同名文件才另取名称。新建后按提交回读并核对 blob 哈希和路径。每篇独立报告，一篇失败继续其他笔记；语义改写须在调用程序前由代理实际比对，不能假称程序自动理解全部语义。

## 返回每篇实际结果

逐项提供最终路径与下列状态之一：

- **已提交且已验证**：真实提交 SHA/链接、回读内容一致；可计入已保存 N/M。
- **重复跳过**：真实已有路径、读取内容/指纹证据，本次无文件写入、无新提交，单独计数。
- **已存在且验证完成**：仅用于不确定请求后的核对，给出查到的真实提交，不声称本次新建。
- **已提交、未验证**：有真实提交，但回读失败或不一致，列明原因，不计入已验证数。
- **提交失败/未上传**：错误阶段及可重试文件，不伪造提交 SHA。
- **结果不确定**：超时等导致无法确认，保留候选路径待核对，不盲目重传。

只有本次新建与重复跳过项均验证完毕才称“本次去重处理完成”，分别统计新增、跳过与失败；不能把全部跳过说成新建了提交。只报告已选目标，Notion 也被选中时分别检查，不能用一边重复代替另一边存在的证据。生成本地文件、git commit 未 push、调用工具但无成功结果均不代表远端保存。不要声称已同步到用户设备上的 Obsidian。
